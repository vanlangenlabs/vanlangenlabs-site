      AI-assisted development method

      AIRFlow describes AI software development workflows as Mermaid diagrams. People view the diagram; AI agents read the original .mmd source. This is a read-only viewer, not an editor or an agent runner.

      Use with AI / Copilot

      Download standard Copilot instructionsPlace this file at .github/copilot-instructions.md in your repository, or merge it into existing instructions. The standard instructions already reference the shared Project workflow; no viewer setup is required.

      Copy AI reference uses the same standard instructions and adds the selected diagram as context. The agent must still enter through Project, not start independently at that diagram.

      Project records and resuming

      In the consuming repository, AIRFlow-managed project records live in .air/; .air/index.md tracks inventory, status and resume state. Phase-specific criteria are in the active Mermaid subflow. The project record contract is detailed reference for approvals, changes and conflicts; consult only the relevant part when needed.

      Project calls the subflows

      Read Project, then follow its sequence and retrieve only the active Mermaid subflow. Follow that phase's embedded criteria and feedback loops; return to Project only after its successful terminal state and required approval. Project determines the next phase.

      The diagram defines the process, not current project state. Read only the relevant entries in the consuming repository's .air/index.md to restore phase, call stack, artifacts, checks and approval evidence.

      For project-specific workflows, keep the Mermaid files in your repo and reference their local paths. For shared remote workflows, pin a release or commit for reproducible instructions. Web access depends on the AI agent's tools and permissions.
