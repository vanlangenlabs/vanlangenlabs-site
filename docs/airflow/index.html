      AI-assisted development method

      AIRFlow helps developers and teams give AI coding agents a clear development process. The agent follows the flows; you approve key decisions.

      Add AIRFlow to a repository

      1. Download the Copilot reference
      2. Save it as .github/copilot-instructions.md in your repository. If that file exists, add the reference to it; keep your existing instructions.
      3. Ask your agent to use AIRFlow for your development task. It reads the online rules and retrieves the flows it needs.

      Your agent needs access to the linked files. You do not need to download the diagrams or set up this viewer.

      New GitHub repository with Copilot

      Start on GitHub without a local checkout. Your initial prompt becomes a task for Copilot's cloud agent, which prepares changes in a branch and opens a pull request for you to review.

      Before you start: sign in to a GitHub account with access to Copilot's coding agent. Availability depends on your plan and organization policies; usage limits may apply. If the Jumpstart option is missing, create the repository normally and use the other setup method.

      Network access: AIRFlow is public, but Copilot's environment can still block it. Allow access to the AIRFlow instructions and flows in the repository's Copilot firewall settings once the repository exists.

      1. Open GitHub's new repository page. Choose the owner, repository name and visibility, and complete the repository settings.
      2. Find Jumpstart your project with Copilot (optional). Paste the prompt below, replacing the project description and constraints with your own. Do not include passwords, tokens or other secrets.
      3. Create the repository with the prompt included. Follow GitHub's link to the Copilot task or pull request. Copilot works asynchronously; the session log shows its progress and any access problems.
      4. In the new repository, open Settings > Copilot > Internet access. Under Copilot in the cloud (not Copilot code review), open Custom allowlist. Add https://vanlangen.org/airflow/, click Add rule, then Save changes. This allows both airflow.md and the underlying flows/ sources. Keep the firewall enabled.
      5. If custom rules are locked by your organization, ask an organization administrator to add the same rule to the organization allowlist or enable repository custom rules. The agent cannot grant itself this access.
      6. If the initial Jumpstart task was blocked before you saved the rule, start a new Copilot task after saving. Ask it to read the repository instructions (or use the Jumpstart prompt again if setup is incomplete), retrieve AIRFlow and resume any existing records without replacing them. Check the pull request body, comments or session log for firewall warnings showing the blocked address and command.
      7. Open the pull request and read its description, changed files and check results. This prompt asks for AIRFlow setup and an initial concept proposal, not a finished application. Check that .github/copilot-instructions.md points to AIRFlow and that no product implementation has started without your approval.
      8. Request changes in the pull request with @copilot and concrete feedback. When AIRFlow asks for a decision, state exactly which record and version you approve. A merge alone is not approval of every AIRFlow record.
      9. Once the setup changes are satisfactory and required checks pass, mark the pull request ready for review if it is still a draft, then merge it when permitted. Continue with a new Copilot task or your local coding agent, asking it to read the repository instructions and resume AIRFlow from .air/index.md.

      Jumpstart prompt

      Set up this new repository to use AIRFlow.

Project idea: [Describe the product, its users and the problem it solves.]
Constraints: [Describe known requirements, preferred stack, or write "not decided yet".]

Read https://vanlangen.org/airflow/airflow.md and follow its Project entry point and referenced source flows. If you cannot access them, report the blocker instead of inventing the workflow.

Create .github/copilot-instructions.md with this reference, preserving any existing instructions:
# AIRFlow
For development work, read and follow https://vanlangen.org/airflow/airflow.md before acting or resuming. It defines the workflow and links to its Mermaid flows. If inaccessible, report the limitation and request an accessible copy; do not guess.

Initialize the consuming project's .air/ records as directed by AIRFlow. Start with the concept for the project idea above. Do not invent missing product decisions or approve records on my behalf. Stop at the first human decision or approval gate and present the exact record version, open questions and next action in the pull request. Do not implement product code before the required approvals.

Use the pull request to explain the setup changes, checks performed and how to resume the workflow.

      If the cloud session stops while waiting for approval, continue in a new task with the same repository records. If access still fails after allowing the URL, inspect the exact fetch error. Some web-reading tools cannot process the MIME type GitHub Pages assigns to .mmd files; use a permitted text-download tool to read the original source. If retrieval remains unavailable, provide an accessible, consistent copy of the instructions and flows before proceeding.
