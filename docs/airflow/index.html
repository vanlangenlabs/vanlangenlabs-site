      AI workflow diagrams

      AIRFlow describes AI software development workflows as Mermaid diagrams. People view the diagram; AI agents read the original .air.mmd source. This is a read-only viewer, not an editor or an agent runner.

      Use with AI / Copilot

      Download standard Copilot instructionsPlace this file at .github/copilot-instructions.md in your repository, or merge it into existing instructions. The standard instructions already reference the shared Project workflow; no viewer setup is required.

      Copy AI reference uses the same standard instructions and adds the selected diagram as context. The agent must still enter through Project, not start independently at that diagram.

      Project calls the subflows

      Always read Project first and follow its sequence. A referenced Mermaid file is a subflow call: retrieve it, follow its steps and feedback loops, then return to Project only after successful completion and the required human approval. Project then determines the next phase; the agent does not freely choose one.

      The diagram defines the process, not the current project state. Record the active phase, approvals and relevant artifacts in the consuming repository so an agent can determine where to continue.

      For project-specific workflows, keep the Mermaid files in your repo and reference their local paths. For shared remote workflows, pin a release or commit for reproducible instructions. Web access depends on the AI agent's tools and permissions.
